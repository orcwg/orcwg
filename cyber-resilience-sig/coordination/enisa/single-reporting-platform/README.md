# Single Reporting Platform — Open Source Community Feedback Hub

Welcome! This repository serves as a dedicated, open space to gather, analyse, and synthesise feedback from the Open Source community regarding the Single Reporting Platform.

Our primary goal is to ensure that the unique workflows, constraints, and needs of the open source community are well-represented as reporting mechanisms for vulnerability and incident reporting evolve.

## 🎯 Purpose & Objectives
* Gather Information: Collect real-world feedback, operational challenges, and technical requirements from open source stakeholders using the SRP.
* Analyse Data: Identify common pain points, regulatory friction, and edge cases in the reporting process.
* Propose Solutions: Formulate actionable, community-backed proposals and recommendations to make reporting seamless and efficient for all stakeholders.

## 🚀 How to Contribute
We collect all feedback, proposals, and discussions directly through GitHub Issues. You do not need to submit code PRs to contribute—your insights and experiences are what matter most.

### Contribution Process
**There is a label to use in all the issues referring to the SRP 'single-reporting-platform'** 

* *Search Existing Issues*: Check the repository’s Issues tab to see if your feedback or concern has already been raised.

* Open a Main Issue:
  * If your feedback covers a new topic, create a New Issue.
  * Provide a clear description, relevant context.
  * Label the issue as 'single-reporting-platform'

* Use Sub-Issues:
  * For complex topics or broad feedback, break down the main issue using sub-issues or GitHub task lists (- [ ] Task).
  * Group related discussions or specific technical requirements under the main parent issue to keep discussions focused.

**Engage in Discussion:** Comment on existing issues to add your perspective, validate proposed solutions, or highlight practical edge cases.
